## 3. 确定性算法

### 3.1 `add` 命令变更
- 新增可选 `--priority high|mid|low` 参数
- 缺省值：`"mid"`
- 非法值（非 `high/mid/low`）：`sys.exit(1)` + 错误提示，**不写入文件**
- 重复 `--priority` 标记：报错退出

### 3.2 `list` 命令
- 不加参数：保持原行为（零回归）
- `--sorted`：按 `high→mid→low` 稳定排序，显示 `[高]`/`[中]`/`[低]` 标记
- 编号恒为存储序（与 `done` 命令编号一致）

### 3.3 `done` 命令
- 不变，编号按存储序

### 3.4 旧数据兼容
- `load()` 中 `it.setdefault("priority", "mid")`

## 4. 守门（反例拦截点）

| 场景 | 预期行为 |
|------|---------|
| `add x --priority urgent` | 报错退出，todo.json 不变 |
| `add x --priority h` | 报错退出 |
| `add x --priority`（缺值） | 报错退出 |
| `add x --priority high --priority low` | 报错退出 |
| 旧 todo.json 无 priority | 读入自动补 mid，不崩溃 |

## 5. 验收标准

1. `python todo.py add 买菜 --priority low` → 已添加: 买菜
2. `python todo.py add 交房租 --priority high` → 已添加: 交房租
3. `python todo.py list --sorted` → high 在前，显示 [高]/[中]/[低]
4. `python todo.py list` → 原录入顺序（零回归）
5. 非法优先级值被拦截

## 评审决策点清单

### 决策点 1：优先级存储格式
- **问题**：`priority` 字段用什么值？
- **选项 A**：全拼 `"high"/"mid"/"low"`（直观，自文档）
- **选项 B**：单字母 `"h"/"m"/"l"`（省空间）
- **默认**：**A**（全拼）

### 决策点 2：排序触发方式
- **问题**：默认就排序还是加参数触发？
- **选项 A**：`list` 默认按优先级排序
- **选项 B**：`list --sorted` 才排序，`list` 保持原行为
- **默认**：**B**（零回归）

### 决策点 3：优先级值校验
- **问题**：是否接受缩写？
- **选项 A**：严格全拼，`h/m/l` 必须被拒
- **选项 B**：宽松，接受 `h`/`m`/`l` 缩写
- **默认**：**A**（严格）

### 决策点 4：排序视图编号
- **问题**：`--sorted` 显示排序序编号还是存储序编号？
- **选项 A**：存储序编号（与 `done` 命令一致）
- **选项 B**：排序序编号（更直观但 `done` 时需换算）
- **默认**：**A**（存储序）

### 决策点 5：优先级标记语言
- **问题**：优先级标记用什么语言？
- **选项 A**：中文 `[高]/[中]/[低]`
- **选项 B**：英文 `[High]/[Mid]/[Low]`
- **默认**：**A**（中文，与 `--sorted` 中文提示一致）
