# 需求文档：todo.py 优先级支持

## 现状结论

- `todo.py` 第 33 行：`items.append({"text": " ".join(rest), "done": False})` — 待办条目无 `priority` 字段
- `todo.py` 第 36-39 行：`list` 命令仅按录入顺序输出，无法区分轻重缓急
- `README.md` 已明确标注「已知局限：不支持优先级」

## 功能需求

### FR-1：添加时指定优先级
`add` 命令支持可选 `--priority high|mid|low` 参数，缺省为 `mid`。非法优先级值写入前硬拦截，不污染数据文件。

### FR-2：按优先级排序展示
`list --sorted` 按 高→中→低 稳定排序输出（同优先级保持录入顺序），并显示优先级标记 `[高]`/`[中]`/`[低]`。`list` 不加参数时维持原行为（零回归）。

### FR-3：确定性排序
相同数据两次 `list --sorted` 输出逐字节一致。

### FR-4：写入前硬拦截
非法优先级值（如 `urgent`、`h`）在写入 `todo.json` 前报错退出，不污染数据文件。

### FR-5：旧数据兼容
旧 `todo.json`（无 `priority` 字段）读入时自动补 `"mid"`，不崩溃、不丢失数据。

## 非功能需求

- **零回归**：`add <文本>`、`list`、`done <编号>` 三个原命令行为不变
- **纯标准库**：不引入第三方依赖
- **确定性**：排序算法稳定，两次运行结果一致

## 竞品对比

| 产品 | 能力 | 边界 | 差异 |
|------|------|------|------|
| todo.txt CLI | 纯文本待办，支持优先级 (A/B/C) | 无 JSON 存储 | 本项目用 JSON，优先级用全拼 high/mid/low |
| taskwarrior | 完整任务管理，优先级 P1-P5 | 重量级，需安装 | 本项目为单文件极简 CLI |
| 原生 Windows 记事本 | 纯文本记录 | 无结构化数据 | 本项目有 done 状态和持久化 |
